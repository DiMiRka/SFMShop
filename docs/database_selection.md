# Выбор баз данных для проекта SFMShop

## 1. Обзор

В проекте SFMShop используется комбинированный подход к хранению данных с применением нескольких технологий:

- PostgreSQL основная реляционная база данных
- Redis кэш и быстрые временные данные
- MongoDB хранение логов

Такой подход позволяет эффективно решать разные задачи хранения и обработки данных

---

# 2. PostgreSQL (основная база данных)

## 2.1 Для каких данных используется

PostgreSQL используется для хранения основных бизнес данных:

- Пользователи (users)
- Товары (products)
- Заказы (orders)
- Позиции заказов (order_items)
- Отзывы (reviews)

---

## 2.2 Почему выбран PostgreSQL

PostgreSQL это надежная реляционная СУБД с поддержкой:

- ACID транзакций
- Сложных JOIN запросов
- Ограничений
- Индексов

Для этих данных важно обеспечивать:

- Консистентность данных
- Связи между сущностями

---

## 2.3 Преимущества

- Полная поддержка ACID (гарантия целостности данных)
- Поддержка транзакций (важно для финансовых операций)
- Гибкие возможности запросов (JOIN, GROUP BY, агрегаты)
- Надежность и стабильность
- Поддержка репликации и масштабирования

---

# 3. Redis (кэш)

## 3.1 Для каких данных используется

Redis используется для хранения:

- Кэшированных данных:
  - списки товаров
  - пользователи
  - заказы
- Часто запрашиваемые данные
- Сессии пользователей

---

## 3.2 Почему выбран Redis

Redis это in-memory хранилище с очень высокой скоростью доступа

Используется для:
- уменьшения нагрузки на PostgreSQL
- ускорения ответа API

---

## 3.3 Преимущества

- Очень высокая скорость
- Хранение данных в памяти
- Поддержка TTL (время жизни ключей)
- Простота использования (key-value)

---

# 4. MongoDB (логи)

## 4.1 Для каких данных используется

MongoDB используется для хранения логов:

- Ошибки
- HTTP запросы
- Системные события
- Отладочная информация

---

## 4.2 Почему выбран MongoDB

Логи имеют следующие особенности:

- Неструктурированные данные
- Разная схема (разные поля)
- Большой объем данных
- Не требуется строгая схема

MongoDB хорошо подходит для таких задач благодаря:

- Гибкой структуре документов
- Отсутствию строгой схемы
- Удобной агрегации

---

## 4.3 Преимущества

- Гибкая структура
- Удобно хранить JSON документы
- Поддержка агрегаций
- Хорошо масштабируется
- Подходит для аналитики логов

---

# 5. Сравнение подходов

| Критерий          | PostgreSQL    | Redis        | MongoDB     |
|------------------|---------------|-------------|-------------|
| Тип данных       | Реляционная   | Key-Value   | Документная |
| Схема     | Фиксированная        | Нет схемы    | Гибкая    |
| ACID         | 	Полная поддержка       | Ограниченная | Ограниченная     |
| Скорость            | Средняя       | Очень высокая         | Высокая      |
| Масштабируемость| Вертикальная | Горизонтальная        | Горизонтальная        |
|Использование|Основные данные|Кэш, сессии|Логи|


---

# 6. Вывод

### Использовать правильный инструмент для каждой задачи

- PostgreSQL обеспечивает надежность и целостность данных
- Redis ускоряет доступ к часто используемым данным
- MongoDB позволяет гибко работать с логами и аналитикой

**Такой подход обеспечивает:**
- высокую производительность
- масштабируемость
- гибкость системы

# Сравнение хостингов для проекта SFMShop

## VPS

VPS это виртуальный сервер с выделенными ресурсами\
Команда сама настраивает сервер, Docker, базу данных, reverse proxy, SSL, обновления и мониторинг

Преимущества:

- Низкая стоимость для небольшой нагрузки
- Полный контроль над сервером и окружением
- Подходит для учебного проекта, MVP или небольшого интернет-магазина
- Можно развернуть Docker Compose с API, PostgreSQL, Redis, MongoDB и RabbitMQ

Недостатки:

- Нужно самостоятельно администрировать сервер
- Нет автоматического масштабирования из коробки
- Сложнее обеспечить отказоустойчивость
- При росте нагрузки придется вручную добавлять серверы, балансировщик и резервное копирование

Где подходит для SFMShop:

- Старт проекта
- Нагрузка до 100 RPS
- Небольшая команда и ограниченный бюджет

## Cloud (AWS, Google Cloud)

Cloud платформы дают управляемые сервисы: Kubernetes, базы данных, балансировщики, хранилища, мониторинг и автоматическое масштабирование

Преимущества:

- Хорошо подходит для продакшен нагрузки
- Есть managed PostgreSQL, Redis, Kubernetes и балансировщики
- Можно настроить горизонтальное масштабирование через Kubernetes HPA
- Высокая доступность и гибкость инфраструктуры
- Удобно масштабировать проект от средней до высокой нагрузки

Недостатки:

- Сложнее настройка по сравнению с VPS и PaaS
- Выше стоимость, особенно при неправильной настройке ресурсов
- Нужно понимать сети, IAM, балансировку, мониторинг и managed-сервисы
- Есть зависимость от конкретного облачного провайдера

Где подходит для SFMShop:

- Средняя нагрузка от 100 до 1000 RPS
- Продакшен с требованием к надежности
- Развертывание через Kubernetes, Deployment, Service, HPA и Secrets

## PaaS (Railway, Render, Fly.io)

PaaS это платформа, где инфраструктурой управляет провайдер\
Обычно достаточно подключить репозиторий, указать переменные окружения и команду запуска приложения

Преимущества:

- Самый простой старт
- Быстрый деплой без ручной настройки сервера
- Удобное управление переменными окружения
- Подходит для учебных проектов, pet проектов и MVP
- Не нужно вручную настраивать сервер, systemd, nginx и SSL

Недостатки:

- Меньше контроля над инфраструктурой
- Ограничения тарифов и платформы
- При росте нагрузки стоимость может быстро увеличиться
- Сложнее развернуть нестандартную инфраструктуру из нескольких сервисов
- Возможна зависимость от возможностей конкретного PaaS

Где подходит для SFMShop:

- Быстрый запуск демо-версии
- Небольшая нагрузка до 100 RPS
- Проверка идеи до полноценного продакшен развертывания

## Сравнение по нагрузке

| Нагрузка | Подходящий вариант | Почему |
| --- | --- | --- |
| До 100 RPS | VPS или PaaS | Дешево и достаточно просто для старта |
| 100-1000 RPS | Cloud или Kubernetes в Cloud | Нужны масштабирование, балансировка и managed-сервисы |
| Более 1000 RPS | Cloud + Kubernetes + Load Balancer + Cache | Нужны горизонтальное масштабирование и высокая доступность |

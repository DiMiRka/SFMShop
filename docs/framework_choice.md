# Выбор фреймворка: FastAPI

SFMShop это REST API без HTML страниц: товары, пользователи, заказы, кэш, очередь, ИИ-ассистент\
Сравнивались FastAPI и Django

## FastAPI

Плюсы:

- **Асинхронность из коробки** \
  БД (SQLAlchemy + asyncpg), Redis, RabbitMQ и Claude API работают без блокировок
- **Pydantic**\
  Валидация запросов и ответов, из тех же моделей строятся JSON-схемы инструментов для LLM
- **Автоматическая документация OpenAPI** (Swagger на `/docs`)
- **`Depends` для внедрения зависимостей**\
  В тестах любой слой подменяется через `dependency_overrides`
- **Нет навязанной структуры**\
  Слои (роутеры, сервисы, репозитории) выбраны под проект

Минусы:

- **Нет встроенных инструментов** (ORM, админки и аутентификации)
- **Больше ручной работы** (JWT, роли и проверки прав написаны в проекте)
- **Экосистема меньше, чем у Django**

Подходит для REST API, микросервисов, асинхронных приложений и бэкенда для SPA

## Django

Плюсы:

- **Инструменты из коробки** (ORM, админка, аутентификация и авторизация)
- **Быстрый MVP и стандартная структура проекта**
- **Большая экосистема**

Минусы:

- **Асинхронность добавлена частично** (ORM в основном синхронный)
- **Жёсткая структура проекта**
- **Избыточен для чистого API**

Подходит для классических сайтов с шаблонами, проектов с админкой и CRUD-систем с простой логикой

## Решение

**Выбран FastAPI:**

- проект это чистый API, админка и шаблоны Django не нужны
- почти каждый запрос ходит во внешние системы (PostgreSQL, Redis, RabbitMQ, LLM), и async даёт здесь главный выигрыш
- Pydantic закрывает валидацию и для HTTP, и для инструментов ИИ-ассистента
- `Depends` и `dependency_overrides` позволяют тестировать без поднятой инфраструктуры

**Цена решения:** аутентификацию, роли и админские операции пришлось писать самостоятельно (`sfmshop/core/security.py`, `sfmshop/core/permissions.py`)

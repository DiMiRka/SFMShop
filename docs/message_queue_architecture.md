# Архитектура асинхронной обработки заказов для проекта SFMShop

## Общая архитектура

Система использует брокер сообщений (RabbitMQ/Kafka) для асинхронной обработки задач после создания заказа

Поток:
POST /orders → OrderService → отправка события (order_created) → очередь → Consumer → обработка задач

---

## Задачи для очереди

Основные фоновые задачи:

- Отправка email уведомлений пользователю
- Обновление аналитики и отчетов (выручка, топ товаров)
- Интеграция с payment service
- Логирование событий
- Кэш инвалидация

Примеры сообщений:
- send_email(user_id, order_id)
- update_report(order_id, total)
- process_payment(order_id)

---

## Producer (OrderService)

- После успешного создания заказа отправляет событие `order_created`
- Передает:
  - order_id
  - user_id
  - список товаров
  - сумму заказа

---

## Очередь сообщений

- Используется RabbitMQ или Kafka
- Очереди:
  - order_events
  - notifications
  - analytics

Функции:
- буферизация нагрузки
- гарантированная доставка сообщений
- decoupling сервисов

---

## Consumer (Worker)

- Подписывается на очереди
- Обрабатывает сообщения асинхронно

Типы воркеров:
- Notification Worker (email)
- Analytics Worker (отчеты)
- Payment Worker

---

## Надежность

- Durable очереди (сообщения сохраняются)
- ACK/NACK подтверждение обработки
- Retry с exponential backoff
- Dead Letter Queue для ошибок
- Idempotency (повторная обработка безопасна)

---

## Обработка ошибок

- Временные ошибки → retry
- Критические ошибки → DLQ
- Логирование ошибок
- Мониторинг неуспешных сообщений

---

## Масштабирование

- Горизонтальное масштабирование Consumer (несколько воркеров)
- Балансировка нагрузки через очередь (каждый воркер берет задачи)

---

## Преимущества

- Не блокирует API
- Повышает производительность
- Упрощает масштабирование
- Повышает отказоустойчивость
